# Methods whose RobustnessTest sweep GTK is known to complain about.
#
# The sweep hands every method hostile values of the right type on purpose, so a GLib
# CRITICAL is an expected outcome for some of them - but only for the ones listed here.
# RobustnessTest::gateAgainstPinnedList() fails a sweep that complains without a line, and
# fails a line whose method has gone quiet, so neither a new leak nor a stale entry hides.
#
# Keyed on the triggering method, never on GTK's wording, which changes between versions.
#
# Before adding a line, check the boundary: if the binding could refuse the value with a
# TypeError/ValueError/LogicException (CLAUDE.md, "Convert at the boundary" and the error
# vocabulary), do that instead. A line here says "GTK's own precondition is the only thing
# that can catch this".
#
# The key is `<class>::<method>#<sweep>`: `#arguments` is the wrong-types/arity sweep,
# `#values` the right-type-hostile-value one, because a method can trip only one of them.
#
# A second column narrows a line to the GTK versions it is true of: `gtk>=4.20` means only a
# GTK that new complains, and an older one is still expected to stay quiet (the line is dropped
# for it, so a complaint would fail the sweep as unlisted). The CI floor is GTK 4.14 and the
# Windows job runs whatever gvsbuild ships, so the same commit meets two GTKs.
#
# `optional` in that column says the complaint depends on the environment rather than on the
# value, so silence does not mean the line is stale. Use it only where no `gtk>=` can express
# the difference: a path GLib resolves against the process cwd (PHP's chdir() does not move it
# under ZTS), or a message only a GTK built with G_ENABLE_DEBUG / G_ENABLE_CONSISTENCY_CHECKS
# emits. The strict half still holds everywhere - a complaint with no line at all fails.
#
# To regenerate after a deliberate change, see tests/README-robustness-pin.md.
Gtk4\GApplication::run#arguments
Gtk4\GApplication::unbind_busy_property#arguments
Gtk4\GtkCssProvider::load_from_bytes#arguments
Gtk4\GtkCssProvider::load_from_bytes#values

# on the Windows GTK, a theme-parser error on the Linux NTS runner.
